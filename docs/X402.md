# Ora — x402 flow

Ora implements the **x402 `exact` scheme on XRPL** (t54's XRPL x402 v2). It uses
the `x402-xrpl` SDK for the wire format and the presigned payer, and runs its
**own in-process facilitator** against XRPL **Testnet** (the hosted t54
facilitator documents only a Mainnet endpoint — see
`docs/evidence/feedback-submissions.md` #1).

## The protected resource

`POST /api/x402/quote` — **Ora's FX & liquidity oracle**. It returns a
**signed, time-limited FX quote** that *locks the settlement rate*. This is
economically meaningful: `settlePayment` calls `verifyQuote` and **refuses to
convert** without a valid, unexpired signed quote. It is not a decorative
micropayment.

## The flow (code: `src/lib/x402/`)

1. **Challenge.** No `PAYMENT-SIGNATURE` header → `402` with
   `PAYMENT-REQUIRED: <base64 JSON>`:
   ```json
   { "x402Version": 2,
     "accepts": [{ "scheme": "exact", "network": "xrpl:1", "asset": "XRP",
       "payTo": "r…oracle", "amount": "1000000", "maxTimeoutSeconds": 300,
       "extra": { "invoiceId": "ora-x402-quote:<intentId>", "sourceTag": 20260530 } }] }
   ```
2. **Client guardrails** (`payForResource`, deterministic): `asset` ∈ allowed,
   `payTo` == the expected oracle wallet, `amount` ≤ the guard max, `network` ==
   `xrpl:1`. A violation throws `X402GuardError` before anything is signed.
3. **Presign.** `XRPLPresignedPaymentPayer` builds an XRPL `Payment` with the
   `SourceTag`, `InvoiceID = SHA256(invoiceId)`, and a memo `MemoData =
   HEX(invoiceId)` (binding = `both`), signs locally, and returns the blob +
   `PAYMENT-SIGNATURE` header.
4. **Retry with proof.** The client re-requests with `PAYMENT-SIGNATURE`.
5. **Facilitator** (`verifyAndSettle`): decode the blob and run the spec's
   pre-submit checks — `x402Version==2`, `scheme=="exact"`, `TransactionType ==
   Payment`, `Destination == payTo`, amount matches, `LastLedgerSequence`
   present, invoice binding present (memo **or** `InvoiceID`), no
   `tfPartialPayment`, `network == xrpl:1`. Then `submitAndWait` and an
   independent `tx` lookup; success requires `validated == true` and
   `tesSUCCESS`.
6. **Release.** The oracle computes the FX quote (`effectiveRate = midRate ×
   (1 − fxSpreadBps/10000)`), signs it (HMAC-SHA256, 5-minute TTL), persists the
   `x402_payments` + `xrpl_transactions` rows, and returns `200 { quote,
   signature, alg }` with `PAYMENT-RESPONSE: <base64 { success, transaction,
   network, payer }>` and an `x-ora-x402-checks` header listing every check.
7. The agent verifies the signature + expiry locally before using the quote.

## Assets

XRP on Testnet (drops). RLUSD (`524C555344…`, issuer
`rQhWct2fv4Vc4KRjRgMrxa8xPN9Zx9iLKV`, `extra.issuer`) is wired through the same
path and used automatically on Mainnet or for any RLUSD-funded wallet.

## Evidence

Every run records the x402 payment hash on `x402_payments.xrplTransactionId` and
an `xrpl_transactions` row (`kind = x402_payment`), shown on the receipt and the
payment detail page with an explorer link. Recorded hashes:
`docs/evidence/xrpl-transactions.md`.
